# Security Documentation Policy

Document only what is established: supported versions that receive fixes (if defined), a
private reporting channel that actually exists (for example GitHub private vulnerability
reporting when enabled), responsible-disclosure expectations, the security update practice
if there is one, and relevant security limitations of the software.

Never invent contacts, keys, bug bounties or response-time guarantees; never promise
maintenance the maintainer has not committed to; never publish exploitable details of
unfixed issues, internal infrastructure or confidential configuration. Describe protections
that exist, not intentions. If no private channel exists, say so.
