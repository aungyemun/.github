# Testing Documentation Policy

Document test environments, frameworks, commands (unit, integration, regression,
end-to-end), platform testing performed and not performed, build validation, exclusions,
skipped tests with reasons, and remaining limitations.

Use precise terms: **implemented** (the test exists), **executed** (it was run, in a stated
environment and version), **passed/failed** (the observed outcome), **skipped** (not run,
with the reason), **not performed** (no such testing). Never report success without
evidence, never describe pending CI as passing, and never present unit-test success as
scientific or clinical validation.
