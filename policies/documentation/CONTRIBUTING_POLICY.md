# Contributing Documentation Policy

Write contributor guidance only when the maintainer wants it, and describe the actual
development model: environment setup, workflow and branches actually used, pull-request
expectations, configured coding conventions and linters, test commands, dependency changes,
and how to report security issues privately.

- Do not state that external contributions are accepted unless the maintainer has decided
  so; say plainly if a project is solo-maintained or closed to contributions.
- Do not impose approvals, sign-offs, agreements or processes the project does not use.
- Do not invent codes of conduct, contacts or response times.
- Link to existing documents instead of duplicating them.
